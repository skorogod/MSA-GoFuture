# GoFuture — архитектурные решения

Репозиторий содержит проектные артефакты перехода GoFuture от монолита к микросервисной платформе. Решения, помеченные в ADR статусом «На рассмотрении», описывают целевую архитектуру и требуют отдельного утверждения перед внедрением.

| Задача | Содержание | Ключевые решения |
|---|---|---|
| [Задача 1](tasks/task_1/README.md) | Декомпозиция монолита и целевая C2-схема | Strangler Fig, доменные сервисы с собственными данными, ACL для переходного периода, Kafka с transactional outbox и Debezium, RabbitMQ для существующих задач Celery. |
| [Задача 2](tasks/task_2/README.md) | Заказ поездки и оплата | Оркестрируемая Parallel Saga, Camunda 8, Kafka-команды и события, компенсации, идемпотентность, DLQ и наблюдаемость. |
| [Задача 3](tasks/task_3/README.md) | Глобальное развёртывание | Четыре хаба, region-владелец поездки, геомаршрутизация, DR-пары, fencing, WAF и защита сервисных связей. |
| [Задача 4](tasks/task_4/README.md) | Платформа данных, ML и BI | Raw/curated слои, Spark, ClickHouse и DataLens, Apache Airflow, MLflow и feature store. |
| [Задача 5](tasks/task_5/README.md) | Мультитенантная платформа партнёров | Изоляция БД на tenant, IAM/SSO, роли, подключение партнёра, Kafka ACL и наблюдаемость. |
